The Core Distinction: Workflows vs. AgentsIn contemporary AI system engineering, "agent" is frequently misapplied to any system that invokes an LLM multiple times. However, Anthropic’s Building Effective Agents establishes a clear architectural division based on control flow:Workflows are deterministic systems where code or explicit human logic controls the sequence of execution. In a workflow, LLMs are embedded into predefined nodes or steps (such as prompt chaining, routing, or evaluator-optimizer loops). The path from input to output is pre-engineered and predictable.Agents, by contrast, are autonomous systems where the LLM dynamically directs its own execution path, selects tools, evaluates intermediate environment feedback (ground truth), and decides when a task is complete.Classification of FL-04 PipelineThe FL-04 "Source-Grounded Study Notes" pipeline built in the previous assignment is strictly a Workflow, specifically a prompt-chaining pipeline.The four stages (Gather $\rightarrow$ Synthesize $\rightarrow$ Draft $\rightarrow$ Format) follow a hardcoded, sequential path.The model does not dynamically choose which step to execute next, nor does it autonomously evaluate whether a step failed and decide to re-rerun a previous node with new parameters. Execution moves linearly along predefined code/prompt bounds.2. What is MCP? (Model Context Protocol)The Model Context Protocol (MCP) is an open standard—often described as the "USB-C port for AI applications"—that decouples AI client interfaces (like Claude Desktop or custom IDEs) from backend data sources and tools. Rather than writing custom integration code for every API or database, an MCP client connects to standardization servers exposing three core primitives:Tools (Model-Controlled): Executable functions exposed to the model (e.g., execute_sql, fetch_webpage, read_file). The LLM’s reasoning engine decides when and how to invoke a tool based on the conversation context and tool descriptions.Resources (Application-Controlled): Passive data entities or contextual documents exposed via standardized URIs (e.g., file:///logs/today.txt or db://schema/users). The host application injects resources into the context window to provide ground-truth data without requiring the model to run code.Prompts (User-Controlled): Reusable workflow templates and system instructions pre-packaged on the server. Users invoke them (often via UI slash commands or shortcuts) to execute standardized tasks using specific arguments.3.
